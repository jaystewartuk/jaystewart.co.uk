Case study

WantToJoin

One link per hostel: tonight's outing, who's going, and where the group is now. Built in a week with the hosts at one hostel.

Role
Research, product, design and engineering
Status
Pilot One hostel, to 14 October 2026
Time
Research to a live pilot in three days
Stack
Cloudflare Workers and D1, PostHog, Claude Haiku · wanttojoin.com

What 2,800 messages showed

Before any code, I read five months of a hostel's guest WhatsApp group.

  • Hosts posted each evening's outing several times a day.
  • Polls got three votes at most.
  • "Where are you?" came up three or four times a week.
  • Tour prices were hidden inside pictures.

So: build for the hosts, not the guests. Hostelworld and SocialStay already do RSVPs, so I built only what they don't: nothing to download, a live meeting pin, and a minimum headcount with a deadline.

Decisions from the evidence

  • Take input as it arrives. The rota came as a photo of the reception chalkboard, so the week view takes those lines.
  • Change the metric when corrected. A host said posting several times a day is her job. The measure became "every post carries the link".
  • Follow the money. A tour promoted for 22 days with no price sold within 15 minutes once a guest got the price. Tours now show price and time.
  • Write down what not to build. No accounts, chat or payments in version one.

AI where it pays

Hosts write every post twice, in English and Spanish. "Write it for me" drafts both from the form; the host edits before saving.

  • Code checks times, day, place and price. One retry, then the host is told what to check.
  • Evals: 50 of 50 drafts pass, 92% first time, 2.2 s median, about $0.0003 a post.
  • The evals caught two bugs in my own checker. Both fixed and tested.

Results so far

Day 1: every host post carried the link (4 of 4), and guests opened the page each time. Nobody tapped "I'm in". It rained, the hostel was nearly empty, and neither outing happened.

When the week ends I'll compare RSVPs with turnout, count "where are you?" messages against the baseline, and ask a second hostel.

How it's built

Cloudflare Workers and D1 on the free plan, server-rendered, installable. Every change gets a pull request, tests and a phone-width check in both languages. A merge deploys, checks the live site and rolls back if that fails. Analytics never send guest names.

Next

If hosts keep using it unprompted and turnout matches RSVPs, I take the numbers to a second hostel. If not, I stop and write up why.
